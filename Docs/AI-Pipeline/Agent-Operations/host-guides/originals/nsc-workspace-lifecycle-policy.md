## Ownership before creation

Every persistent task checkout, standalone clone, linked worktree, review/base/scratch clone, nested repository, capture/restore workspace and tool sandbox has one accountable producer and one workspace ID. Temporary names are no exemption. Parents own helper-created workspaces, including failures/cancellations.

Before creation, the creating owner records an immutable registration receipt. Reuse a suitable owned workspace when isolation/branch safety permit; never share an actively edited checkout. Use existing approved task/job/tool roots and methods. New ad hoc work uses C:/nscrev/work/<owner>/<run-id>/ after registration. Do not change record-bound task paths or existing launcher locations to fit that convention. No new unregistered top-level directory or broad-root git init.

Registration is self-service: **no waiting for Cleanup acknowledgement**. Parents pre-register permitted paths and supply IDs to read-only helpers. If nobody authorized can write registration, hold that new creation until someone can; do not expand helper permissions. Ordinary work in already registered workspaces continues under existing authority.

Record planned source/parent before creation, then confirm actual Git identity immediately afterward. Until confirmed, identity remains pending and retirement is forbidden. Partial/failed creations get result and closeout receipts too. Each persistent nested repo gets its own ID linked to the enclosing workspace; the bounded test-fixture exception below covers transient fixtures.

### Bounded transient test fixtures

Persistent means a workspace that survives or is intended to survive the creating test invocation, contains real work/recovery material, or is used by another job/session. Register it individually, including a base/review clone retained between commands. A temporary name alone grants no exception.

For an already authorized test suite that generates synthetic, reproducible temporary repositories, register one exclusively owned bounded test sandbox before launch. Its registration names the exact sandbox root, suite/command, producer, fixture-creation method and evidence destination outside disposable fixture directories. Random child names generated by the suite need not each be pre-registered. They must stay within that sandbox, with no links/dependencies into unrelated material. The suite's existing fixture teardown is unchanged; this exception grants the agent no broader cleanup authority.

At closeout the parent records the run's fixture accounting (root, suite, creation method, result and any enumerated children), checks for surviving repositories/processes and lists every leftover with its actual path. Individually register any retained or unexpected leftover before reuse; hold it if identity is uncertain. Preserve every log and unique result outside fixture teardown. If a suite cannot confine its generated fixtures or protect its output, record that limitation and fix the test setup instead of claiming this exception. Do not demand a separate receipt for each already-removed synthetic fixture.

## Receipt and index contract, version 1

Protected registry: C:/nscrev/reports/cleanup/workspace-registry/. Producers write unique JSON receipts under inbox/<workspace-id>--<event-id>.json. Create each final file once; never overwrite a receipt or another producer's event. Corrections explicitly supersede prior events. Write a temporary sibling, then rename to a unique final filename without overwriting. Readers ignore incomplete temporary files and list abandoned ones as exceptions.

| Common field | Meaning |
|---|---|
| schema_version, event_id, event_type, recorded_at_utc | Version 1, unique event ID, kind and actual UTC time |
| workspace_id, absolute_path | Stable ID and exact path; never reuse an ID for replacement content |
| owner_role, parent_run_id, purpose | Creator accountable for it, session/job/run identity, task/purpose |
| supersedes_event_id | Prior event being corrected, or null |
| details | Event-specific facts below; unknowns explicit |

**register details:** allowed root, creation method, intended Git kind, exact source path/remote and commit where applicable, planned parent/common store, enclosing workspace ID, expected output/log destinations, known dependencies/children, next checkpoint and authority reference. Never include credentials/token values.

**created details:** actual canonical path, Git kind, gitdir/common-dir/store identity and source OID, outputs/children, process/launcher identifiers and discrepancies. Resolve Git indirection with Git and the actual parent's registrations, not filename guesses. Configs containing secrets belong in protected capture handling, not a public ledger.

**checkpoint / closeout details:** success/failure/cancelled/handoff status; expected-artifact validation; exact refs/OIDs; dirty/index/untracked/ignored classification; all log/output paths; child IDs and process/launcher state; current consumers; pending preservation/publication; named next owner/checkpoint. Handoff names a successor rather than orphaning work.

**release details:** exact identity, output closure/execution settlement evidence, dependencies/consumers, owner acknowledgement and named writer/launcher hold through the intended retirement operation. Release is revocable with a hold event. A resumed writer revokes release before writing. If this cannot be enforced, hold the workspace.

**hold / recovery_verified / batch_ready / retired details:** blocker/owner/next action or linked immutable capture, remote-restore and action receipts as applicable. Only Cleanup records accepted retirement states; retired requires Vincent's execution and verified actual outcomes. Producers cannot grant themselves destructive authority with an event.

Cleanup alone writes the derived index.md: one row per ID with path, owner, kind/store, state, latest receipt, blocker/checkpoint, recovery and batch IDs. Do not create competing indices. Immutable receipts remain the source of facts; index updates never erase conflicts. Automation for validation/locking is a PM task, not assumed present.

## Producer closeout

Every success, failure, cancellation, abandoned experiment and session handoff needs an update. The parent reconciles every actual workspace, nested repo, child and output against the packet before accepting a helper return. Require three separate results:

1. **Artifact accepted:** files exist, schema/content, assigned-input coverage and result semantics checked. Exit zero alone is not success; an artifact does not erase a failed command.
2. **Execution settled:** exact processes/containers and owned descendants exited, outputs closed, launchers/controllers cannot restart or publish into the workspace. A marker or stopped parent is insufficient.
3. **Owner released:** explicit exact-path release after settlement, or a named hold with next checkpoint.

Prefer stable per-run evidence outside retiring checkouts. Preserve **all logs**, prompts/answers and unique output required by the durability plan. Tools writing inside a clone must report exact paths and preserve them before retirement. Never casually relocate hash-bound art/evidence. A recorded destination is not proof of upload or recovery.

## Lifecycle and eligibility

registered -> active -> closing -> released -> recovery-verified -> batch-ready -> retired

Any non-retired state can be held with reason, owner, last valid state and next action. Changed identity/content, resumed writers, unknown dependencies or conflicting releases invalidate readiness. Recreated retired paths need new IDs. States record facts, never confer permission.

The Cleanup guide defines retirement gates: reverse Git/runtime dependencies, writer holds, full stable fingerprints, complete capture, fresh per-candidate remote restore, copy policy, explicit task/dirty decisions and independently reviewed human execution. Age/silence never advance state. No timeout deletion, force, wholesale quarantine expiry or reset to obtain clean status.

Existing unregistered material is inherited debt: protect it, seed active/protected roots first, import legacy inventory by partition. Do not declare old items disposable or require a perfect global ledger before the first fully proven batch. New work must comply as soon as its creating session adopts these instructions.

## Bounded maintenance and capacity

These are duties at agreed checkpoints, not a scheduler installed by this change:

- Producers reconcile IDs at start, completion and handoff; missing closeout becomes a named owner action.
- Cleanup processes new receipts and changed entries each authorized session, recording cursor/coverage. Periodically reconcile approved creation roots and known Git parents, including nested declarations. Show unscanned areas.
- Creators check disk headroom for source, outputs and recovery overlap before large jobs. Use measured resource limits; agent availability is not disk capacity. Cleanup-sprint cloning, hashing, capture, compression and restore share the team's initial global two-heavy-stream budget.
- At agreed maintenance windows Vincent gets small verified batches and exceptional decisions. Show execution backlog separately from preservation backlog.
- Coordinate restore drills at agreed maintenance cadence and after archive/schema changes. Each deletion candidate still needs its own independent proof.

Metrics: new registrations, new unregistered discoveries, active/closing/held/retired counts, missing closeouts, unrecovered released material, log-source coverage, oldest owner blocker, eligible/reclaimed measured bytes, capture/remote-verification/full-restore timestamps. Show date, scope and unscanned remainder. Targets: zero new unregistered repos, zero missing closeouts, zero unverified retirements. Age is escalation only.

Escalate concrete repeated violations to the responsible producer/launcher owner and Vincent through authorized channels. One concise blocker table suffices; silence remains a hold. Do not halt unrelated work or accelerate deletion to meet a cleanliness target.
