## Prevention and closeout

Use the [shared workspace lifecycle policy](C:/NSC/nsc-workspace-lifecycle-policy.md) and [Cleanup guide](C:/NSC/nsc-cleanup-agent-guide.md). Before persistent workspace creation, its producer registers owner/run/task, exact path/source/common store, outputs/logs, dependencies and intended closeout. Parent producers close every success, failure, timeout, interruption and abandonment with actual refs, dirty/ignored state, all outputs, active descendants, pending publication and retirement intent. Successor sessions inherit unresolved workspace IDs.

Cleanup uses the shared policy lifecycle: registered, active, closing, released, recovery-verified, batch-ready and retired, with held as an exception. Closeout/preservation/decision needs belong in blocker and next-action columns, not a separate state vocabulary. Each blocked row has an owner. Start by registering active work and new jobs; import historical rows incrementally. Reconcile registered roots to expose unregistered births rather than repeating whole-disk forensics. No age, silence, TTL or empty log implies retirement.

Keep logs in stable evidence roots where possible without breaking existing hash-bound paths. Parent closeout captures clone-local logs explicitly. Measure new/closed/retired workspaces, unregistered paths, closeout age, archival/approval backlog, recovery age and retained/reclaimed space. Notify on useful batches, required decisions or capacity issues. This is an operating contract; no launcher enforcement, automation or deletion service is claimed installed.

The final report distinguishes measured execution, each protected source/cutoff, actual deleted IDs/space, active registered owners, held paths/blockers, repeat capture, second-copy receipts, prevention backlog and deferred engineering. One safe batch may finish while another is held. Full durability and whole-project cleanup remain incomplete until their respective evidence exists.

Full task undo, broad tool migration, junction retirement, historical midpoint recovery, viewer code and experimental merge decisions remain outside this cleanup's critical path. Preserve their assigned owners and later interfaces; do not turn them into today's dependency chain.
