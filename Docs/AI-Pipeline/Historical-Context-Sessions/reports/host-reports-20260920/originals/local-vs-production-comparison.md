## 4. Design: production mirrors local; a human PASS where local auto-accepts

Principle: the human PASS replaces `local_candidate_auto_accept` at exactly one point — after C is committed and pushed, before the serial integrator touches main. Everything after the PASS is machine-only and never waits on a human again unless the trunk conflicts with the candidate (the same case local refuses).

5. **Dependents and "delivered".** No overlay. After publication the scheduler's `source_main_refreshed` moves the controller source to M; `_LazyTaskcontrolStateProvider` derives `conformant` for the task; `dependencies_dispatch_satisfied` admits dependents. A later merge that changes a surface turns it into `needs_testing`, which `dispatch_policy.json` still treats as satisfied — exactly local's `LOCAL_ACCEPTED_DEPENDENCY_STATE`, but derived from committed evidence. The smallest honest record is therefore the **existing DEL record + `select` event, produced by `record_delivery.py` unchanged, at C instead of at a post-merge commit**; the merge must prove "surfaces unchanged", which is TaskGraph's own currency rule, instead of "human re-tested the merge commit". Merge (not `apply` like local) is required because `_evaluate_resolved_conformance` needs C reachable from main (`record_object_unavailable` L423, ancestor L432) and `verify_post_merge_and_complete` clones main single-branch.
