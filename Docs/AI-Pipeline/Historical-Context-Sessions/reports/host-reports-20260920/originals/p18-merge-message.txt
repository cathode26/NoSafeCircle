Merge fix/content-identical-churn: refresh Git's stale stat cache for content-identical churn

Pipeline Maintainer fix P18. Windows checkouts accumulate tracked files that Git reports as modified while their filtered content equals the index blob, because the recorded size is stale. `git status` never re-hashes them, so a clean-tree gate refuses a worktree whose content is in fact unchanged.

- New `Pipeline/TaskReviewAgent/refresh_identical_churn.py`, exposed as `safe_unity_churn refresh-identical`. It refreshes only the index stat entries of tracked, worktree-modified, unstaged, regular files whose filtered hash equals the index blob. It never rewrites worktree files, never stages a real edit, re-hashes each file immediately before `git add`, restores the index byte-identically on any failure, refuses while `index.lock` exists, and defaults to a dry run.
- `safe_unity_churn.main` takes an optional argv and dispatches the new subcommand; existing callers import `classify_safe_post_unity_churn` and the test runner's `--repository/--expected-head/--apply` invocation is unchanged.
- `decomposition.py`'s "Source must be clean" error now names the command.
